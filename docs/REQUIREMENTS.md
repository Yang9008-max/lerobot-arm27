## 2. 硬件事实（实测）

### 2.1 机械臂（证据来自 `D:\MyTrain\projects\27_engineer`，全仓库只读）

| 关节 | 电机 | CAN 主/从 ID | 减速 | 限位 |
|---|---|---|---|---|
| J1 底座回转 | DM4310 | 0x01 / 0x11 | 1:1 | ±2.5 |
| J2 肩俯仰 | DM-J8009P | 0x02 / 0x12 | 1:2 | 软 [-5.35, 0.462] |
| J3 肘俯仰 | DM-J8009P | 0x03 / 0x13 | 1:1 | [-2.5, 3.15] |

- 连杆：`h_s=240`、`l_se=300`、`l_et=338`（mm），肩偏置 `C2=2.783074`、`C3=-2.771681`
- 总线：**FDCAN2 经典帧 1 Mbps**（底盘 4× M3508 在 **FDCAN1**，两条总线互不干扰）
- 控制模式：底 MIT（底盘使能时切位置速度）；肩/肘恒 **MIT + 重力前馈**；肘 `t_max=54 N·m`
- **运动学只建了 th2/th3 平面两连杆，yaw 不进运动学**；笛卡尔接口只有 2D `(r,z)` + 独立 yaw

### 2.2 控制器

- STM32H723 + FreeRTOS，C++20（禁堆），CMake + Ninja，DAPLink/OpenOCD 烧录
- **唯一已验证的 PC 通道：UART7 @921600 8N1，且只有 H7→PC 方向**
  - 20 Hz 打两行文本：`kin,...` 与 `watch,...`
  - `watch` 已包含：`qb/qa/qe`、`th2/th3`、末端 `r/z`、三轴速度/力矩、使能/安全位、**全部遥控通道值**
  - PC 侧现成可用脚本：`tools\arm_watch.py`（COM8，921600）
- **PC→H7 方向不存在任何协议**：UART7 的 DMA 接收已启动，但回调是空函数，收到的字节被丢弃
- `minipc_comm` 是 RoboMaster 自瞄云台遗留（下发的是**云台角不是关节角**），全工程无调用者且被 CMake 排除 → **不可用**
- USB CDC 是 CubeMX 原版，接收即丢、发送无调用者 → **不可用**
- 全仓库 **无 LeRobot / 模仿学习 / 数据集 / 相机 / ROS 的任何提法**，固件**没有**为上位机策略预留钩子

### 2.3 遥控器

- HT-10A，SBUS 25 字节帧，16 通道原值 + 具名摇杆/开关/旋钮（中位 992，三档 0/32/64）
- 映射在 `cmd.cpp`：右三档是总闸（DOWN 解锁 / MID 底盘 / **UP 臂**）；只有 UP 才积分摇杆
- **遥操作是速率积分式**：摇杆积分成目标角。存进数据集的 action 是**绝对关节角**，恰好就是 ACT 要学的量

### 2.4 相机

- Orbbec Gemini 2，`VID_2BC5&PID_0670`，四路设备（Data Channel / RGB / IR / Depth）**全部在线**
- 本机已装 `pyorbbecsdk2 2.1.2` —— 驱动层已通
- **安装方案（已变更）**：从 eye-in-hand 改为**固定在臂旁看工作区的第三方视角**，由机械组做结构件
  - 变更原因：eye-in-hand 在**无腕关节**时视角完全由 J2/J3 决定、剧烈摆动；相机线缆随臂运动；
    而且**给末端加了质量会让已辨识的重力前馈参数（`arm.h:311-341`）全部失效**；深度做物体定位还要手眼标定
    （而 FK 只建了 th2/th3，yaw 尚未进入运动学）
  - 改为固定机位后：**臂的质量分布不变，现有重力模型继续有效**；**深度直接就是工作区坐标，不需要手眼标定**，
    恰好解锁了「深度用于后处理/物体定位」这个原始需求
  - 待定细节：斜俯视 30–45°（而非纯侧平视，避免自遮挡与沿光轴运动不可见）；注意 J1 限位 ±2.5 rad = ±143°，
    相机需覆盖实际工作扇区或用任务限制 yaw 范围
  - **分辨率已实测定案：用 640×480@30，不要用 1280×720。** 在 Ryzen 5 5600U 上实测录制循环速率：
    640×480 → **29.16 fps**（周期 34.3 ms，比 30 差 2.8%，可接受）；1280×720 → **19.96 fps**（周期 50.1 ms）。
    LeRobot 的时间戳按 `frame_index / fps` 生成，所以 1280×720 会让数据集时钟比现实快 1.50 倍，**该分辨率下的录制不可用于训练**
  - ⚠️ **机位一旦定下不可再动**：换了机位等于换了观测分布，之前采集的数据全部作废
- **RGB 进策略，深度不进策略**（LeRobot 主线 ACT 默认只吃 RGB），深度录进数据集备用
- 形状：**RGB-D**

## 3. 架构决策

### 3.1 已采纳

> **切面放在「目标关节角」：PC（LeRobot：策略推理 + 数据采集 + 相机）→ UART7 → H7（重力补偿 + 软限位 + 联锁 + 1kHz MIT 伺服）**

> 🔒 **遥控器必须保留为安全保险（用户明确要求，不可协商）。**
> - 阶段 1：天然满足——PC **不下发任何指令**（`send_action()` 是空操作，`read_only=True`），
>   遥控器是唯一指令源，本身就是保险。
> - 阶段 2（自主推理，PC 开始下发目标角）必须落实为**固件层的否决权**：
>   1. 右三档仍是总闸——**只有 UP 时 H7 才接受 PC 下发的目标角**；DOWN 立即硬停并忽略 PC；
>   2. **超时失能**——PC 若 ~200 ms 未发新指令，H7 自动停止跟随并交回遥控器控制；
>   3. 遥控器摇杆随时可接管（优先级高于 PC）。
> - 这三条是阶段 2 固件方案的门禁条件，未实现前不得开启 PC 下发。

理由：ACT 推理只有 10–30 Hz，而 MIT 力矩控制需要 ≥1 kHz——**这两件事本来就不该由同一个东西干**。让实时性留在 MCU，LeRobot 只做它擅长的事。

### 3.2 已否决的方案及原因

| 方案 | 否决原因 |
|---|---|
| **PC 直驱 CAN + H7 退场** | ① 臂**装在工程车上**，H7 同时管 4× M3508 底盘，不可能真"退场"；② 达妙电机同时刻只能有一个主控，H7 仍会用遥控器写 `arm_cmd`，**照样要改固件**，"省掉改固件"是错觉；③ 必须重写肩/肘重力前馈（RMSE 0.285 / 0.686 N·m）、软限位、肩肘联锁、顶住判定、电机心跳——**补不上前馈臂会直接往下掉，这是安全问题**；④ 固件无过温/超速切断，无 PC 掉线保护 |
| `minipc_comm` 复用 | 自瞄云台遗留，下发云台角，无调用者，CMake 已排除 |
| USB CDC 复用 | 接收即丢数据，发送无调用者 |
| 深度进策略 | 工程量上升，ACT 默认只吃 RGB，收益不明确 |
| 换游戏手柄 / STM32 做 USB HID | H7 中转架构下**不需要**——HT-10A 经 H7 已可用，手感不用改 |
| 换同构 leader arm | 无此硬件，且 H7 中转下现有遥操作已足够 |

### 3.3 关键简化：阶段 1 **零固件改动**

`watch` 遥测已包含全部遥控通道值 + 关节角。而 H7 本来就在用遥控器驱动臂。所以：

> **采集阶段 PC 只读，不下发任何指令** —— `watch` + Gemini2 帧配对即可录成 LeRobotDataset。

反向通道（PC→H7 + 超时失能）**只在推理阶段才需要**。这把阶段 1 的固件风险降到零。

## 6. 关键风险

| # | 风险 | 缓解 |
|---|---|---|
| R1 | **`watch` 只有 20 Hz**，数据集通常要 30–50 Hz | 阶段 1 先接受 20 Hz 验证链路；提速属改固件，阶段 2 一并评估 |
| R2 | **时间戳对齐**：文本遥测 20 Hz vs 相机 30 FPS | 统一用 PC 单调时钟打时间戳，落盘后按时间插值对齐；不要依赖到达顺序 |
| R3 | **C 盘只剩 3.5 GB**，`pip`/HuggingFace 缓存默认写 `C:\Users\...\.cache` | 第一步就设 `HF_HOME` / `PIP_CACHE_DIR` / `TMPDIR` 到 D 盘 |
| R4 | **相机支架尚未存在**，是关键路径上的外部依赖 | 阶段 1a/1b 先用第三方视角或手持，**不要等结构件**——pipeline 与安装方式无关 |
| R5 | **末端执行器会改变质量分布**，现有重力参数（`arm.h:311-341`）装夹爪/腕后必然失效 | 阶段 2 或硬件到位后**重新标定**；在此之前不要把旧参数当真值 |
| R6 | **固件无过温/超速切断，且无 PC 掉线保护** | 阶段 2 必须自己写超时失能；PC 侧也要有看门狗 |
| R7 | 臂在车上、笔记本用 USB-TTL 拴在 COM8、相机线随臂运动 | **采集时底盘必须锁死**；线束要留冗余 |
| R8 | 无腕时夹爪朝向完全由 J2/J3 决定，姿态受限 | 属机械组/赛季需求问题，本项目按黑盒处理 |
| R9 | ⚠️ **本机 `workspace-write` 模式下 `pwsh` 无法启动**（`0xC0000142`），已排除 ACL 原因（脚本判定 `NOT_THIS_CLASS`） | 需将会话切到完全权限，否则每条命令都要单独提权 |
